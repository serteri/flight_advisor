## Phase 2 — Safe Migration Adapter (same session)

### What Happened
- Created `lib/adapters/toUnifiedFlight.ts` — the bridge from FlightResult to UnifiedFlight
- Single new file, zero existing files touched

### Functions Created
1. `toUnifiedFlight(flight: FlightResult): UnifiedFlight` — core pure adapter
2. `toUnifiedFlights(flights: FlightResult[]): UnifiedFlight[]` — batch with error isolation
3. `fromUnifiedForScoring(unified: UnifiedFlight): FlightResult` — reverse bridge for scoring

### Key Design Decisions
- Universal `normalizeSegment()` handles ALL provider field variations defensively
- If segments array is empty, creates synthetic segment from flight-level data
- Tuple type `[FlightSegment, ...FlightSegment[]]` enforced
- `mapSource()` validates against VALID_SOURCES set (defensive, should never fail)
- Baggage/policies only included in output when meaningful data exists

### Runtime Impact
- ZERO — adapter file exists but is NOT imported or called anywhere
- No pipeline changes, no response changes, no scoring changes

## Phase 4 — Feature Flag Routing (same session)

### What Happened
- Created `lib/featureFlags.ts` — env-based flag module (USE_UNIFIED_PIPELINE, UNIFIED_DEBUG)
- Modified `searchService.ts` — conditional routing: flag ON = roundtrip through UnifiedFlight, flag OFF = legacy
- Modified `flight-search/route.ts` — gated scoring: flag ON = applyAdvancedFlightScoringUnified, flag OFF = legacy

### Key Design Decisions
- Flags read at call time (not module load) for Next.js hot-reload
- Both flags default to false — zero-risk deployment
- Conversion failure auto-falls-back to legacy path
- Error handler returns pipelineMode: 'legacy'
- useUnifiedDebug() replaces raw `process.env.UNIFIED_DEBUG` check for consistency
